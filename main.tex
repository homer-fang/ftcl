\begin{cnabstract}
\cnabstracttext{许多算法原型在脚本表达与 GPU 执行之间存在断层：脚本足够灵活，却难以触达设备计算；CUDA 足够强大，却要求使用者管理内存、指针和同步。本文设计并实现 FTCL，一个 Tcl 风格的算法实验脚本系统，并将其扩展为面向计算几何的 CPU/CUDA 混合执行平台。系统以 UVec 管理 CPU 与 CUDA 缓冲区，通过有效标记维护最新副本，并以 \texttt{geom} 命令暴露距离矩阵、最近点、范围计数和 AABB 碰撞等批量几何算法。实验从语义回归、CPU/GPU 等价、随机差分、单 GPU 与八卡 A800 扩展性等方面验证系统。结果表明，紧凑输出任务可获得明显 CUDA 与多 GPU 加速，而输出密集型距离矩阵受内存分配和带宽限制。最后，本文将 FTCL 应用于海洋牧场感知、智慧港口、无人机巡检和船舶碰撞检测，说明其可作为脚本驱动的异构空间计算原型平台。}

\cnkeywords{脚本解释器；Tcl；计算几何；UVec；CUDA；多 GPU}
\end{cnabstract}

\begin{enabstract}
\enabstracttext{Algorithm prototypes often break at the boundary between expression and execution: scripts are flexible but rarely reach the GPU, while CUDA is powerful but forces users to manage memory, pointers, and synchronization by hand. This thesis designs FTCL, a Tcl-style scripting system for algorithm experiments, and extends it into a CPU/CUDA hybrid computational geometry platform. Its central abstraction is UVec, a cross-device vector that keeps CPU and CUDA buffers consistent through validity flags and on-demand synchronization. On top of UVec, FTCL exposes a script-facing \texttt{geom} command library for distance matrices, nearest-point queries, circle range counting, affine transformations, and AABB collision checks. The system is evaluated through semantic regression, CPU/GPU equivalence, random differential testing, single-GPU benchmarks, and eight-GPU A800 weak-scaling experiments. The results show that compact-output workloads obtain clear CUDA and multi-GPU speedups, whereas output-heavy distance matrices are limited by allocation and memory bandwidth. Finally, the thesis maps FTCL to marine ranch sensing, smart port safety, UAV water-surface inspection, and ship collision checking, showing that FTCL is a prototype heterogeneous spatial-computing platform rather than a standalone geometry library.}

\enkeywords{Scripting interpreter; Tcl; Computational geometry; UVec; CUDA; Multi-GPU}
\end{enabstract}

\JOUBackmatterChapter{结论与展望}
本文完成了一个从 Tcl 风格解释器出发、并逐步扩展为 CPU/CUDA 混合计算几何脚本平台的端到端系统。FTCL 目前已支持实用的语言子集、线程通道、UVec 跨设备向量、CPU 几何算法、CUDA kernel、测试框架、基准流水线与论文图表生成流程。实验结果表明，当工作项足够多且彼此独立时，GPU 后端能够带来明显收益；但当输入规模过小、输出过大或需要立即读回时，并行执行的优势会被启动、分配、同步与数据搬运成本抵消。

后续工作可从四个方向继续推进。第一，UVec 应进一步向标准向量接口对齐，包括迭代器、容量管理、插入/删除以及更强的异常安全保证。第二，CUDA 后端应加入内存池、异步 stream 与更好的批处理，以降低分配与同步成本。第三，解析路径可以继续向 token-stream 解析、AST 表示、字节码执行与表达式级 Pratt 解析演进。第四，几何库可以扩展空间索引、动态最近邻搜索、多边形布尔运算，并构建更贴近海洋牧场、智慧港口、无人机巡检与船舶避碰的应用演示。

FTCL 的价值不只是“能运行几何命令”，而是把脚本层表达、跨设备内存、并发执行与可复现实验放进同一个系统边界中。未来最重要的方向，是将 FTCL 从原型平台发展为可复用的异构空间计算运行时。
